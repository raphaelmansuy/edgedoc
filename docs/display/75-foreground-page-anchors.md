# Foreground page anchors

EdgeDoc can now place a non-wrapping, page-relative foreground picture in a body paragraph, without treating it as an inline picture or adding its height to text flow. It paints the picture after the paragraph containing its anchor and before later paragraphs, as Wordcraft does. The existing behind-text variant remains behind the body. The diagnostic recognizes this bounded body case; header and footer anchors and wrapped pictures continue to be diagnosed.

A controlled document places a foreground image at a known page offset over several paragraphs. The EdgeDoc and Wordcraft images were inspected: an initial implementation painted the picture over later paragraphs, which the broad pixel threshold did not catch. The corrected order passes the strict glyph and raster comparison with zero unmatched ink and zero common-ink color error. A separate centered-page alignment variant also passes. Regression tests check picture position, order relative to the anchor and later text, and the continued diagnostic for header anchors.

The exact-source benchmark recorded 12 passes, 34 failures, and 2 blocked Wordcraft reference timeouts; all 209 selected previous passes passed again. See `word-benchmark-48-front-anchor-summary.json` and `front-anchor-regression-209-summary.json`. The workspace passed 411 tests and strict Clippy; the rebuilt browser passed 18 interaction checks and 134 checks across 33 documents. The square-wrapped logo in `418b154e5c` remains unsupported and visibly shifts the first-page text; this work does not establish general floating-picture parity.
