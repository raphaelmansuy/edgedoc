# Fixed-width floating tables anchored to a margin

EdgeDoc now supports a restricted floating-table case: a table with fixed layout or an explicit point width, anchored horizontally to the margin and vertically to the following text, with explicit nonnegative vertical offset, optional horizontal offset, and wrap distances. The table takes its measured width and creates a float exclusion instead of reserving its height in ordinary flow. Unsupported anchor forms and other floating-table cases retain the diagnostic and existing fallback.

The controlled fixture at `target/wordcraft-parity/floating-table-simple` matches Wordcraft's page in glyphs, origins and raster ink. Three horizontal and vertical offset variants also match, and the horizontally offset pages were inspected visually. An automatic-layout fixture with an explicit width also matches. The downloaded `wordbench-056bfeba7c` now has Wordcraft’s four pages instead of five. Its last two pages have zero unmatched ink but fail the color threshold; other page differences and unsupported paragraph frames remain. The third-page Wordcraft and EdgeDoc images were inspected.

The offset variants exposed a word-breaking issue when a float leaves two bands. EdgeDoc now retries a whole word in the next band, and, when neither band can hold the first word, moves that word below the float. Controlled long-word fixtures with and without preceding text match Wordcraft; unit tests cover both band selection and moving below the float. These comparisons still report the floating-table diagnostic because general floating-table support is incomplete.
