# Image-only parity evidence

The comparison gate previously required text on at least one page and therefore rejected image-only documents even when their rendered pictures matched. It now accepts a textless case only when both SVGs contain the same embedded raster-image bytes, the image has visible nonwhite pixels, both page rasters contain meaningful ink, and every page still passes the normal dimensions, unmatched-ink, and color thresholds. Unsupported rendering diagnostics and reference-adapter limitations remain failures. Blank, transparent, missing, or different image evidence is rejected.

Nine downloaded Apache POI and docx4j image-only examples pass the revised focused comparison (`image-only-focused-result.json`). The header-picture page and a seven-image page were visually inspected in both engines (`image-only-image-inspection.json`). These are newly recognized evidence, not nine new rendering fixes. The negative gate tests cover blank, missing, transparent, mismatched, and unsupported cases; all 16 gate tests and six external-corpus helper tests pass.

The complete current-source, revised-gate run is `image-evidence-final-394-result.json`: **211 passed, 165 failed, and 18 blocked**. Compared with `wordwrap-final-394-result.json`, thirteen cases changed from failed to passed: nine image-only examples accepted by the new evidence rule and four plain table-style cases accepted by the narrower style diagnostic. No existing status regressed. These comparisons use the pinned Wordcraft revision and the recorded font profile; substantial gaps remain.
