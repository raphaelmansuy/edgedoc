# Adjacent paragraph borders

Wordcraft's `crates/layout/src/boxes.rs` groups consecutive paragraphs with matching borders and indents. On `6b651ce4d7` from the pinned Word-exported benchmark, EdgeDoc previously added the top and bottom border allowance around each paragraph. The extra space accumulated by 16 points per boundary and displaced the subsequent content across pages.

EdgeDoc now joins adjacent body paragraphs when they have directly specified, matching top/bottom border sets and matching left/right indents. It reserves the top border only for the first and the bottom border only for the last, and omits the interior horizontal borders. This is deliberately restricted to border sets without sides, between edges, or shading; the complete Wordcraft border-box behavior also connects side borders and shading and remains future work.

With the locally installed Word font profile, the reused Wordcraft reference and the new EdgeDoc output pass the strict comparison on all five pages, including zero unmatched ink. The regression verifies border suppression, line spacing and that a different indent breaks a group. The first and fifth pages of each render were visually inspected. The supplied Word-exported PDF also has five pages, but its first page has a different border arrangement from both engines; matching Wordcraft here does not establish exact Microsoft Word parity. Inputs remain local and are identified by the pinned manifest in `tests/corpus/word-benchmark-manifest.json`.

A subsequent recheck of all 48 benchmark documents using the installed Word fonts passed 5 and failed 43, with no blocked cases. The Wordcraft renders were reused only after checking the input, Wordcraft source identity and complete font profile; the previously timed-out document's reference completed in a longer retry. Compared with the earlier run, the five-page border-group case became a pass and the other prior passes remained passes. The aggregate evidence is recorded in `word-benchmark-48-border-group-summary.json`.
