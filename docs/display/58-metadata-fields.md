# Metadata fields

Wordcraft uses the document's core title and creator for empty `TITLE` and `AUTHOR` field results, and uses `Document1` for an empty `FILENAME` when no filename is supplied. EdgeDoc now follows those rules and applies the supported capitalization switches in order, ignoring switches inside quoted arguments. Nonempty cached results remain unchanged. Empty results for other field commands no longer insert a visible-width placeholder. Fields whose behavior is not covered continue to produce an unsupported-layout diagnostic.

`metadata-fields-before-result.json` and `metadata-fields-focused-result.json` record the synthetic before/after comparison; the latter has zero glyph-position error, unmatched ink, and common-ink color error. Its visually inspected page pair is in `metadata-fields-image-inspection/`. A downloaded Apache POI `FldSimple.docx` containing a saved `FILENAME` field also passes (`real-metadata-fields-result.json`), with its inspected page pair in `real-metadata-fields-image-inspection.json`.

The 196-case current-source run plus that separately checked real document gives 197 distinct passing cases under identical engine fingerprints (`metadata-197-result.json`). Workspace tests, strict clippy and formatting checks passed, along with 18/18 browser interaction checks and 134/134 checks on 33 corpus documents. The latest full 394-case run, before this metadata change, is `picture-final-394-result.json`: 195 passed, 181 failed, 18 blocked.

Wordcraft's layout code also leaves `CREATEDATE`'s saved result unchanged. EdgeDoc already did the same, so that specific command no longer receives the generic unsupported-field diagnostic; other unimplemented commands still do. The downloaded POI `FieldCodes.docx` with `AUTHOR` and `CREATEDATE` now passes, as does `FldSimple.docx` (`real-metadata-fields-final-result.json`); the first page of each pair was inspected (`createdate-image-inspection.json` and `real-metadata-fields-image-inspection.json`).
