# Character indents and picture cropping

The pinned Word-exported document `153b511c02` exposed two independent gaps. First, a `w:hangingChars="327"` value was interpreted as 327 characters instead of 3.27. Text consequently began thousands of points outside the page and the last two pages diverged. OOXML character indents are hundredths of a character; EdgeDoc now uses that unit for left, right and first-line character indents, while preserving the original integer in edited files. A regression exercises both a two-character left indent and a fractional hanging indent.

Second, the document contains two pictures with `a:srcRect` crop values. EdgeDoc previously rendered the full image, while Wordcraft applies the crop. The model now retains the four crop values, the reader and writer round-trip them, and flow passes the normalized source rectangle to the image operation. The browser already uses this rectangle when drawing to canvas; SVG now clips and scales the same source rectangle. A regression covers the image operation, SVG output and edited-save preservation.

With the installed Word font profile, the document now passes the strict Wordcraft comparison on all six pages. The second and fifth pages were visually inspected in both engines and against the Word-exported PDF. This is evidence for these examples, not full document parity. Six other previously passing Word-benchmark documents also pass after the crop change; this is a seven-case focused recheck rather than an updated 48-case total. The input is identified by the pinned manifest in `tests/corpus/word-benchmark-manifest.json`.

A subsequent full recheck of the 48 Word-benchmark inputs, using the same installed-font profile and verified Wordcraft references, passed 7 and failed 41, with no blocked cases. This is two additional passes compared with the earlier border-group run. The source, input, reference, font-profile and comparison-tool fingerprints and per-document statuses are recorded in `word-benchmark-48-crop-summary.json`. Fresh per-case EdgeDoc SVGs were discarded after their comparisons to conserve disk space; the specifically inspected images, Wordcraft references and original documents remain available.

A separate four-document check added locally installed Tahoma, Verdana and Impact faces to the font profile. Those substitutions disappeared, but all four documents still failed for other recorded layout or reference-adapter reasons; see `word-font-expanded-focused-summary.json`.

The rebuilt browser viewer was also opened on `153b511c02`. Its second-page canvas was inspected and showed the cropped image; the viewer reported six pages and no browser errors. The standard browser suite passed 18/18 interaction checks and 134/134 checks across 33 corpus documents.

A separate current-renderer check selected 209 case IDs from the earlier 214-pass evidence that had verified reference output in the retained 394-case corpus. All 209 passed. A temporary-space guard initially deferred 115 cases; those cases all passed on a serial retry with matching renderer and reference fingerprints. The combined results and input manifest are summarized in `current-regression-209-summary.json`. This selected regression result does not replace the 48-document benchmark or prove overall parity.
