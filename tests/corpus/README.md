# The downloaded corpus

Date: 2026-11-04. Part of the EdgeDoc Display specification. See [../README.md](../README.md).

The [expanded corpus](EXTERNAL.md), added on 2026-11-05, includes another 75 pinned Apache POI
and docx4j documents, including long technical guides and complex rendering regressions.
It has a separate Wordcraft geometry/pixel gate. The browser checks below are smoke checks;
they do not establish reference rendering parity.

These 33 documents come from the [python-docx](https://github.com/python-openxml/python-docx)
project, which publishes them under the MIT licence as its own test fixtures. They are real
Word files, written by Word and edited by hand, not generated by this library. That is why they
matter: a document this library wrote cannot show a reader that it reads a document someone else
wrote.

## Why a downloaded corpus

The synthetic documents in `crates/edgedoc-demos` are built by the fluent API that this
repository owns. They prove that the reader and the writer agree. They cannot prove that the
reader understands a file that Word wrote 15 years ago. They also cannot prove that the writer of
that file used an element this library never emits.

The first run of this corpus found that 12 of the 33 files did not open at all. The cause was a
whitespace node after the root element, which Word writes and the package parser refused. The
synthetic corpus could not find that defect, because the library's own writer does not put that
whitespace there.

## The run

```bash
cargo run -q -p edgedoc-display --example corpus -- tests/corpus/downloaded
```

The program opens every file, lays it out, and prints one line per document:

```
document                            pages  glyphs    ink px       ms
blk-containing-table.docx               1       0         1       99
blk-paras-and-tables.docx               1     161       176      189
comments-rich-para.docx                 1     107       122      154
doc-access-sections.docx                3      79        90      130
...
33 ok, 0 failed, 33 total
```

`glyphs` counts the painted text elements, and `ink px` counts the characters that the text layer
holds. A document with no `w:t` element shows 0 in both columns, which is correct: a structural
fixture holds no text.

## The checks

`node tools/display_corpus_e2e.mjs` runs the browser test over this corpus. It loads each
document in the viewer and asserts:

| Check | What it proves |
|---|---|
| Every file opens | The package parser reads what Word writes |
| The page count is at least 1 | Layout never returns an empty document |
| A document with text paints text | The reader, the shaper, and the painter agree |
| A document with a table paints a rule | The table path runs |
| The text layer holds the characters | Selection and search work on a real file |
| A header or footer paints above or below the body | The story parts resolve |
| No page paints outside its own size | Geometry stays inside the page |

## What the first run found

| Defect | Files | Cause | Fix |
|---|---|---|---|
| The package would not open | 12 | A text node after the root element, which Word writes | Text outside the root is ignored (`crates/edgedoc-opc/src/xml.rs`) |
